# 埋点与数据指标方案

## 1. 原则

- 业务事实优先取服务端事件；曝光、点击和授权弹窗取客户端事件。
- 事件名稳定、属性可扩展，不把枚举值编码进事件名。
- 每个事件包含 event_id、event_time、user_id（登录后）、anonymous_id、session_id、app_version、platform、community_id、current_dog_id、source_page、trace_id。
- 不采集明文手机号、精确坐标、健康详情、评论正文、图片内容或支付凭证。
- 客户端事件可补发但不可用于确认支付、成行、退款等最终事实。

## 3. 指标口径

### 3.1 北极星指标

`weekly_effectively_interacting_dogs`：自然周内至少发生一种有效互动的去重 active dog_id 数量。

有效互动事实：

1. 该狗狗发布的内容收到另一用户的有效评论；
2. 两只不同主人的狗狗在当周形成相互关注；
3. 狗狗对应报名记录为 ATTENDED 且邀约完成；
4. 狗狗参加平台认证线下活动并完成签到；
5. 狗狗对应幼儿园订单进入 COMPLETED。

排除运营测试账号、员工账号、自评自互动、已撤销/判违规事件和重复补发事件。

### 3.2 核心漏斗

| 阶段 | 分母 → 分子 | 建议观察窗 |
|---|---|---|
| 登录转化 | 二维码落地 UV → 登录成功 UV | 24 小时 |
| 档案创建 | 登录成功新用户 → 创建首只狗狗 | 24 小时 |
| 档案完成 | 创建首只狗狗 → 场景必填完成 | 7 天 |
| 社区加入 | 创建首只狗狗 → 加入社区 | 24 小时 |
| 首日互动 | 加入社区 → 首次发帖/有效评论/关注/报名 | 当日 |
| 首次发布 | 加入社区 → 发布通过审核 | 7 天 |
| 邀约报名 | 访问邀约详情去重狗 → 提交报名 | 7 天 |
| 邀约确认 | 报名 → CONFIRMED | 单次邀约 |
| 邀约成行 | CONFIRMED → ATTENDED 且邀约完成 | 单次邀约 |
| 幼儿园预约 | 服务详情去重狗 → 支付成功 | 30 天 |
| 幼儿园复购 | 首单完成狗 → 第二单完成 | 90 天 |

### 3.3 留存与质量

- D1/D7/D30 留存：首次创建有效狗狗身份日为 cohort 起点，回访需发生有效会话。
- 内容质量：发布通过率、有效评论率、举报率、下架率。
- 邀约质量：申请响应时长、确认率、成行率、临时取消率、爽约率、安全异常率。
- 服务质量：评估通过率、支付转化、容量利用率、签到率、异常率、接回准时率、退款率、复购率。
- 治理质量：举报处理时长 P50/P90、申诉改判率、严重事件首次响应时间。

## 4. 数据模型与去重

- 事件表按 `event_id` 幂等；业务事件同时保存业务主键与状态历史 ID。
- 用户、狗狗、社区和门店维表采用缓慢变化维，支持按事件发生时口径回溯。
- 测试、运营、审核、幼儿园员工账号通过统一 `account_class` 排除。
- 指标 SQL 版本化，仪表盘展示口径说明、数据截止时间和负责人。
- 评价修改、举报改判和退款回调采用可重算事实，不直接覆盖历史事件。

## 5. 看板与告警

### 每日运营看板

- 新增用户、首只狗狗、社区加入、首日互动；
- 内容发布/审核积压/举报；
- 今日邀约、确认人数、成行与取消；
- 评估、预约、到店、服务中、待接回、退款；
- 严重安全事件与超 SLA 工单。

### 每周产品看板

- 北极星指标及构成；
- 核心漏斗、D1/D7 留存；
- 社区互动密度（有效互动狗数 / 周活狗数）；
- 邀约供需、成行、爽约和复约；
- 幼儿园转化、复购、异常和评价。

### 实时告警

- 登录、发帖、报名、支付回调成功率显著下降；
- 容量出现负数或同一订单重复扣款；
- R3 举报、严重托管异常、活动集中取消；
- 通知积压、审核队列超 SLA；
- 精确位置或高敏感字段疑似出现在日志/响应。

## 6. 验证

- 开发环境提供事件调试台，不发送到生产数据集。
- 测试逐项核对事件触发一次、属性类型、匿名到登录身份合并和补发去重。
- 灰度首周每天抽样对账：数据库业务事实、事件明细和看板聚合。
- 发布新事件或改口径必须包含 schema 版本、兼容期、回填策略和负责人。
