# MVP 功能分级、角色与用户故事

## 1. 优先级清单

| 领域 | P0 | P1 | P2 |
|---|---|---|---|
| 账号 | 微信登录、协议同意、主人资料、注销 | 登录设备管理 | 多平台账号 |
| 狗狗身份 | 创建/编辑/切换、多犬管理、公开与敏感字段隔离 | 档案完成度、认证勋章 | 成长时间轴 |
| 社区 | 邀请码加入、社区切换、社区认证 | 主理人申请 | 跨社区关系推荐 |
| 动态 | 图文发布、列表/详情、点赞、评论/回复、删除 | 收藏、关注流、热门狗狗 | 高级编辑、话题运营 |
| 治理 | 审核、举报、拉黑、处罚、申诉入口、审计 | 反作弊策略配置 | 自动化信用分 |
| 附近 | 定位授权、模糊距离、附近狗狗、隐身 | 今日可约、公共地点 | 智能匹配排序 |
| 邀约 | 创建、报名、审批、取消、提醒、快捷状态、完成、互评 | 候补、重复邀约 | 固定搭子计划 |
| 幼儿园 | 详情、项目、要求、申请、评估、预约、支付状态、签到、服务、日报、异常、接回、评价 | 优惠、可视化排班 | 多商户 |
| 通知 | 站内通知、关键订阅消息 | 聚合与免打扰 | 个性化触达 |
| 运营后台 | 用户/内容/社区/举报/处罚/配置/审计 | 活动运营、数据看板 | 自动化运营 |
| 幼儿园工作台 | 档案、评估、容量、订单、签到退、日报、异常、退款处理 | 员工排班 | 多门店结算 |
| 数据 | 核心埋点、漏斗、错误监控 | 留存与分群看板 | 推荐实验平台 |

说明：举报、拉黑、位置保护和托管异常属于 P0，不因“后台功能”而降级。

## 2. 用户角色

| 角色 | 目标 | 关键权限边界 |
|---|---|---|
| 游客/未登录用户 | 了解产品与登录 | 不可查看社区成员、附近和用户内容 |
| 犬主 | 经营狗狗身份、互动、邀约、预约 | 仅管理本人及名下狗狗；敏感数据自主授权 |
| 邀约发起人 | 组织安全的线下遛狗 | 审批报名，不得查看报名者私人联系方式 |
| 社区主理人 | 发布官方活动、协助社区运营 | 只管理授权社区，不处理敏感健康信息 |
| 内容审核员 | 审核内容和举报 | 可查看取证内容，不可查看无关健康或支付数据 |
| 运营管理员 | 管理社区、用户处罚、申诉与配置 | 高风险操作需原因、审计，不能修改支付结果 |
| 幼儿园员工 | 评估、签到、日报、接回 | 仅访问服务所需狗狗资料和本门店订单 |
| 幼儿园店长 | 容量、服务、退款建议、员工管理 | 只限本门店；退款资金动作按财务权限 |
| 客服/风控 | 处理投诉、安全事件和售后 | 按工单临时授权，访问留痕 |
| 超级管理员 | 角色与系统配置 | 最小人数、强认证、全量审计 |
| 系统任务 | 审核、提醒、支付同步、超时流转 | 服务身份、固定权限、幂等执行 |

## 3. 用户故事

### 3.1 犬主与狗狗身份

- 作为新犬主，我希望用微信快速登录并创建第一只狗狗，以便立即看到相关社区内容。
  - 验收：协议未同意不能创建；必填字段校验；创建后自动设为当前狗狗。
- 作为多犬家庭，我希望切换当前狗狗，以便用正确身份发帖、报名和预约。
  - 验收：所有写操作保存 dog_id；切换不会改变既有内容归属。
- 作为犬主，我希望分别控制附近可见和健康资料授权，以便保护隐私。
  - 验收：关闭附近可见后不进入他人附近结果；敏感资料未授权时员工不可见。
- 作为注销用户，我希望删除个人资料。
  - 验收：先处理未完成邀约/订单；完成身份核验；按法定保留要求匿名化或删除并给出结果。

### 3.2 内容社区

- 作为犬主，我希望以狗狗身份发布图文，以记录生活。
  - 验收：显示狗狗身份；审核未通过不公开；作者可删除。
- 作为犬主，我希望评论、回复和关注其他狗狗，以形成社区关系。
  - 验收：拉黑双方不可互动；回复只支持一层；通知可追溯到原内容。
- 作为被骚扰用户，我希望拉黑并举报。
  - 验收：拉黑即时生效；举报回执不暴露处理人员和被举报人隐私。

### 3.3 附近与邀约

- 作为犬主，我希望筛选附近合适的狗狗，但不暴露具体住址。
  - 验收：仅展示模糊距离和公共区域；无定位权限时给出替代入口。
- 作为发起人，我希望设置时间、公共集合点和参与条件，以降低线下风险。
  - 验收：不能输入联系方式/门牌；开始时间必须在未来；人数受上限控制。
- 作为参与者，我希望报名并获得接受或拒绝结果。
  - 验收：重复报名幂等；拒绝可选标准化原因；状态变化发通知。
- 作为已确认参与者，我希望发送“已到达”等快捷状态。
  - 验收：仅活动窗口内、仅已确认成员可发送；不支持自由文本。
- 作为参与者，我希望活动后如实确认和评价。
  - 验收：评价在双方提交或窗口结束后展示；异常评价进入风控队列。

### 3.4 幼儿园服务

- 作为首次入园犬主，我希望提交档案并预约评估。
  - 验收：健康信息需单独授权；未评估通过不能支付正式服务。
- 作为员工，我希望记录评估结论和限制条件。
  - 验收：只有本门店授权员工可操作；结论、理由、时间和操作者留痕。
- 作为犬主，我希望查看可预约日期并支付。
  - 验收：容量锁定防超卖；支付回调幂等；订单保存价格快照。
- 作为犬主，我希望服务期间收到日报和异常通知。
  - 验收：日报仅订单监护人和授权员工可见；严重异常强提醒并记录触达。
- 作为员工，我希望完成签到、接回和异常记录。
  - 验收：流转符合状态机；接回需确认或线下凭证。

### 3.5 运营与治理

- 作为审核员，我希望在一个队列处理机器命中的内容。
  - 验收：展示必要上下文；支持通过、拒绝、下架、升级；全程审计。
- 作为运营人员，我希望处理举报、处罚和申诉。
  - 验收：处理人与申诉复核人原则上分离；严重安全事件进入专门工单。
- 作为店长，我希望配置每日容量。
  - 验收：不能将容量降到已确认订单以下；修改影响有明确提示和日志。

## 4. P0 发布闸门

以下任一未完成不得开启真实用户灰度：

- 精确位置和敏感健康资料无法通过接口越权获取；
- 举报、拉黑、内容下架和安全事件升级链路不可用；
- 幼儿园评估前可绕过支付或出现容量超卖；
- 微信支付回调非幂等、退款状态不可对账；
- 注销、审计、隐私授权和生产数据隔离未经验证；
- 关键状态机没有后端强校验；
- 严重事件无人值守或未定义联系人。
