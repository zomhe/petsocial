# 狗狗身份字段与业务状态机

## 1. 字段分级

- L0 公开：在社区规则和隐私设置允许时展示。
- L1 社交受限：仅登录且满足社区/附近规则的用户可见。
- L2 服务敏感：仅主人及获得特定服务授权的员工可见。
- L3 高敏感：严格最小权限、加密存储、访问审计，不用于公开展示。

## 3. 邀约模型字段

邀约至少包含：发起狗狗、社区、公共地点、日期、开始/结束时间、最大狗狗数、体型要求、性格要求、行为排除项、注意事项、是否审批、取消临界时间、状态、版本号。

报名至少包含：邀约、参与狗狗、申请状态、条件快照、申请/决定时间、决定人、取消原因、到场事实、完成事实、异常引用。

## 4. 遛狗邀约状态机

### 4.1 邀约主状态

```mermaid
stateDiagram-v2
  [*] --> DRAFT
  DRAFT --> OPEN: 发布
  DRAFT --> CANCELLED: 放弃
  OPEN --> FULL: 确认人数达上限
  FULL --> OPEN: 有人取消且仍可报名
  OPEN --> LOCKED: 到达报名截止
  FULL --> LOCKED: 到达报名截止
  OPEN --> CANCELLED: 发起人/平台取消
  FULL --> CANCELLED: 发起人/平台取消
  LOCKED --> IN_PROGRESS: 到达开始时间
  LOCKED --> CANCELLED: 紧急取消
  IN_PROGRESS --> PENDING_CONFIRMATION: 到达结束时间
  PENDING_CONFIRMATION --> COMPLETED: 完成确认或确认窗口超时
  PENDING_CONFIRMATION --> DISPUTED: 出现争议/安全异常
  DISPUTED --> COMPLETED: 运营结案
  CANCELLED --> [*]
  COMPLETED --> [*]
```

| 状态 | 中文 | 可执行动作 |
|---|---|---|
| DRAFT | 草稿 | 编辑、发布、删除 |
| OPEN | 可报名 | 报名、审批、取消 |
| FULL | 已满员 | 已报名者取消、发起人取消 |
| LOCKED | 报名截止 | 快捷状态、紧急取消 |
| IN_PROGRESS | 进行中 | 到场状态、异常上报 |
| PENDING_CONFIRMATION | 待完成确认 | 到场/完成事实、评价草稿 |
| DISPUTED | 争议处理中 | 补充证据、运营处理 |
| COMPLETED | 已完成 | 评价、查看结果 |
| CANCELLED | 已取消 | 查看原因、按规则记取消事实 |

### 4.2 报名状态

```text
PENDING（待确认）
  → CONFIRMED（已确认）
  → ATTENDED / NO_SHOW / CANCELLED（到场 / 爽约 / 已取消）
PENDING → REJECTED / CANCELLED
CONFIRMED → CANCELLED / REMOVED
```

- 自动确认只在无需审批、满足条件且容量原子扣减成功时发生。
- `NO_SHOW` 不由单方评价直接写入；需双方事实、平台规则或运营复核。
- 发起人移除已确认成员必须选择原因并通知；临近活动的异常移除进入风控抽样。

### 4.3 快捷状态

`ON_TIME`、`LATE_10_MIN`、`ARRIVED`、`CANNOT_ATTEND`、`DOG_UNWELL`、`REQUEST_CANCEL`。快捷状态是事件，不替代报名或邀约主状态。

## 5. 幼儿园评估与订单状态机

### 5.1 评估状态

```mermaid
stateDiagram-v2
  [*] --> APPLICATION_DRAFT
  APPLICATION_DRAFT --> ASSESSMENT_PENDING: 提交申请
  ASSESSMENT_PENDING --> ASSESSMENT_SCHEDULED: 确认评估时间
  ASSESSMENT_PENDING --> USER_CANCELLED: 用户取消
  ASSESSMENT_SCHEDULED --> ASSESSING: 到店开始
  ASSESSMENT_SCHEDULED --> USER_CANCELLED: 用户取消
  ASSESSING --> PASSED: 通过
  ASSESSING --> PASSED_WITH_RESTRICTIONS: 附限制通过
  ASSESSING --> NOT_SUITABLE: 不适配
  PASSED --> EXPIRED: 有效期结束
  PASSED_WITH_RESTRICTIONS --> EXPIRED: 有效期结束
```

评估是独立实体；订单引用有效评估及限制快照。

### 5.2 订单主状态

```mermaid
stateDiagram-v2
  [*] --> PENDING_APPLICATION
  PENDING_APPLICATION --> PENDING_ASSESSMENT: 提交
  PENDING_ASSESSMENT --> NOT_SUITABLE: 评估不适配
  PENDING_ASSESSMENT --> PENDING_PAYMENT: 评估通过并选定服务
  PENDING_PAYMENT --> RESERVED: 支付成功
  PENDING_PAYMENT --> USER_CANCELLED: 取消/支付超时
  RESERVED --> CHECKED_IN: 到店签到
  RESERVED --> CANCELLATION_PENDING: 用户或门店申请取消
  CHECKED_IN --> IN_SERVICE: 开始服务
  IN_SERVICE --> READY_FOR_PICKUP: 服务结束
  IN_SERVICE --> SERVICE_EXCEPTION: 发生服务异常
  SERVICE_EXCEPTION --> IN_SERVICE: 处置后继续
  SERVICE_EXCEPTION --> EARLY_PICKUP: 需提前接回
  READY_FOR_PICKUP --> COMPLETED: 接回确认
  EARLY_PICKUP --> COMPLETED: 接回确认
  COMPLETED --> REVIEWED: 提交评价
  CANCELLATION_PENDING --> REFUNDING: 需退款
  CANCELLATION_PENDING --> USER_CANCELLED: 无需退款
  REFUNDING --> REFUNDED: 退款成功
  REFUNDING --> REFUND_FAILED: 退款失败
```

### 5.3 异常与投诉采用正交子状态

订单主状态之外记录：

- `exception_status`: NONE / OPEN / CONTAINED / CLOSED；
- `complaint_status`: NONE / SUBMITTED / PROCESSING / RESOLVED / APPEALED / CLOSED；
- `payment_status`: UNPAID / PROCESSING / PAID / FAILED / PARTIALLY_REFUNDED / REFUNDED；
- `refund_status`: NONE / REQUESTED / APPROVED / PROCESSING / SUCCEEDED / FAILED / REJECTED。

这样可避免“投诉处理中”覆盖“服务已完成”等业务事实。

### 5.4 状态迁移约束

- 只有有效评估才能从待评估进入待支付。
- 支付回调以微信交易号幂等，前端“支付成功”不能直接改订单状态。
- 签到、服务开始、日报、异常、待接回和接回必须由授权门店员工操作。
- 退款结果以支付渠道回调或主动查询为准。
- 每次迁移写入状态历史：旧状态、新状态、操作者、原因、时间、请求幂等键。
